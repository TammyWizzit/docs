The Users API lets you manage membership in your Wizzit workspace. You can list current members, invite new users by email, update a member's role, and remove access — all programmatically. This is particularly useful for syncing team membership with your identity provider, automating onboarding and offboarding, or building internal tooling on top of Wizzit's access model.

<Note>
  Only users with the **Admin** role can invite new members or remove existing ones from the workspace. Requests from keys or users without Admin privileges will receive a `403 Forbidden` response with the error code `insufficient_scope`.
</Note>

---

## GET /users

Retrieve a paginated list of all members in your workspace. You can filter by role to view only admins, editors, or viewers.

### Query Parameters

<ParamField query="role" type="string">
  Filter members by role. Accepted values: `admin`, `editor`, `viewer`.
</ParamField>

<ParamField query="page" type="integer" default="1">
  The page number to retrieve.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Number of results per page. Maximum is `100`.
</ParamField>

### Example Request

```bash
curl "https://api.wizzit.com/v1/users?role=editor&limit=10" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Example Response

```json
{
  "success": true,
  "data": [
    {
      "id": "usr_01hx9r6ms1",
      "name": "Jordan Lee",
      "email": "jordan@example.com",
      "role": "editor",
      "status": "active",
      "joined_at": "2024-01-15T09:00:00Z"
    },
    {
      "id": "usr_01hx9r8pt3",
      "name": "Sam Rivera",
      "email": "sam@example.com",
      "role": "editor",
      "status": "active",
      "joined_at": "2024-02-20T11:30:00Z"
    }
  ],
  "meta": {
    "page": 1,
    "per_page": 10,
    "total": 2
  }
}
```

## POST /users/invite

Invite a new user to your workspace by email. Wizzit sends the invitee an email with a link to accept the invitation. The user will appear in the workspace member list with a `pending` status until they accept.

### Request Body

<ParamField body="email" type="string" required>
  The email address of the person you want to invite.
</ParamField>

<ParamField body="role" type="string" required>
  The role to assign to the invited user. Accepted values: `admin`, `editor`, `viewer`.
</ParamField>

### Example Request

```bash
curl https://api.wizzit.com/v1/users/invite \
  -X POST \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "newteammember@example.com",
    "role": "editor"
  }'
```

### Example Response

```json
{
  "success": true,
  "data": {
    "id": "usr_01hxar2nv6",
    "email": "newteammember@example.com",
    "role": "editor",
    "status": "pending",
    "invited_at": "2024-05-22T10:00:00Z"
  }
}
```

Returns `201 Created` on success.

## GET /users/{id}

Retrieve the profile of a specific workspace member.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the user (e.g., `usr_01hx9r6ms1`).
</ParamField>

### Example Request

```bash
curl https://api.wizzit.com/v1/users/usr_01hx9r6ms1 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Example Response

```json
{
  "success": true,
  "data": {
    "id": "usr_01hx9r6ms1",
    "name": "Jordan Lee",
    "email": "jordan@example.com",
    "role": "editor",
    "status": "active",
    "joined_at": "2024-01-15T09:00:00Z"
  }
}
```

### Response Fields

<ResponseField name="id" type="string">
  The unique identifier of the workspace member.
</ResponseField>

<ResponseField name="name" type="string">
  The member's display name.
</ResponseField>

<ResponseField name="email" type="string">
  The member's email address.
</ResponseField>

<ResponseField name="role" type="string">
  The member's current role: `admin`, `editor`, or `viewer`.
</ResponseField>

<ResponseField name="status" type="string">
  The membership status: `active` or `pending` (invitation not yet accepted).
</ResponseField>

<ResponseField name="joined_at" type="string">
  ISO 8601 timestamp of when the user joined the workspace. `null` if the invitation is still pending.
</ResponseField>

## PATCH /users/{id}

Update a workspace member's role or other profile details. This is most commonly used to promote a member to a higher role or downgrade their access.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the user to update.
</ParamField>

### Request Body

<ParamField body="role" type="string">
  The updated role to assign. Accepted values: `admin`, `editor`, `viewer`.
</ParamField>

<ParamField body="name" type="string">
  Updated display name for the user.
</ParamField>

### Example Request

```bash
curl https://api.wizzit.com/v1/users/usr_01hx9r6ms1 \
  -X PATCH \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "role": "admin" }'
```

### Example Response

```json
{
  "success": true,
  "data": {
    "id": "usr_01hx9r6ms1",
    "name": "Jordan Lee",
    "email": "jordan@example.com",
    "role": "admin",
    "status": "active",
    "joined_at": "2024-01-15T09:00:00Z"
  }
}
```

## DELETE /users/{id}

Remove a member from your workspace. The user loses access immediately and will no longer appear in the member list. Their previously created documents remain in the workspace.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the user to remove.
</ParamField>

### Example Request

```bash
curl https://api.wizzit.com/v1/users/usr_01hx9r6ms1 \
  -X DELETE \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Response

Returns `204 No Content` with an empty body on success.
