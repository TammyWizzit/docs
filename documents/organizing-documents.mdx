As your document library grows, keeping everything findable becomes just as important as keeping it accurate. Wizzit gives you three complementary tools to stay organised: collections for hierarchical grouping, tags for flexible cross-cutting labels, and a powerful search that works across both. Used together, these features make it easy for your team — and your clients — to find exactly what they need.

## Collections

Collections work like folders: they group related documents under a named container so you can browse by project, client, department, or any other dimension that makes sense for your organisation.

**Creating a collection in the dashboard:**

1. Open the **Collections** section in the left sidebar.
2. Click **New Collection**.
3. Enter a name and an optional description.
4. Add documents to the collection by searching for them in the document picker.

A document can belong to more than one collection, so you're not forced to choose a single home for content that spans multiple projects.

## Tags

Tags are freeform labels you attach to documents to make them easier to filter and discover. Unlike collections, tags don't impose a hierarchy — they're a lightweight way to group documents across collections by theme, status, audience, or any other attribute.

You can add tags when you first create a document, or update them at any time using a `PUT` request:

```bash
PUT https://api.wizzit.com/v1/documents/{id}
```

```json
{
  "tags": ["onboarding", "2024"]
}
```

This replaces the existing tag list on the document with the array you provide. To append tags without losing existing ones, retrieve the current tags first with `GET /documents/{id}`, merge the tag arrays, then send the full updated document in your `PUT` request.

## Search

The search bar at the top of the Wizzit dashboard lets you filter your entire document library in real time. You can search by title, tag, document type, or author — and combine these filters to narrow results precisely.

**Searching via the API:**

```bash
GET https://api.wizzit.com/v1/documents?type=client-facing&tag=quarterly&limit=20
```

Supported query parameters include `type`, `tag`, `author`, `visibility`, `collection_id`, and `limit`. Results are returned in reverse chronological order by `updated_at` by default.

## Best Practices

A consistent organisational approach from the start saves a lot of cleanup work later. Here are a few guidelines worth building into your team's workflow.

<Tip>
  **Use consistent tag naming conventions.** Decide upfront whether you'll use lowercase, hyphens, or underscores in tag names — for example `client-onboarding` vs `client_onboarding` — and document the convention somewhere your whole team can reference it. Mixed tag styles are one of the most common sources of duplicate, hard-to-filter content.
</Tip>

<Tip>
  **Archive rather than delete documents.** Deleting a document is permanent and can break any links or API references pointing to it. Archiving hides the document from default views and prevents it from being shared, while keeping it recoverable and searchable for workspace members who need to refer back to it.
</Tip>

<Tip>
  **Create collections per client or project.** A dedicated collection for each client or project gives you a clean, browseable home for all related documents. Pair this with a shared tag — for example `acme-corp` — and you'll be able to find content both by browsing the collection and by filtering in search.
</Tip>
